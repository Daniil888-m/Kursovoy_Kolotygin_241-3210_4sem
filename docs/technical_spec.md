# Техническое задание: сайт-портфолио художника

## 1. Назначение

Учебный сайт показывает художественные работы и позволяет посетителю связаться с художником, оставить отзыв с оценкой или комментарий. Художник управляет содержимым через административную панель Django. Проект рассчитан на локальный запуск для демонстрации курсовой работы.

Основа задания: методичка «Задания для курсовой работы», разделы «Основные задания (для получения оценки удовлетворительно)» и «Сайт портфолио художника». Здесь описан **фактически реализованный учебный объём**, а не все возможные функции из примерного варианта.

## 2. Роли и возможности

### Администратор (художник)

Для доступа в `/admin/` пользователь должен иметь право `is_staff`. Администратор может:

1. Добавлять, редактировать, публиковать и удалять работы, загружать их изображения.
2. Управлять категориями, стилями и техниками работ.
3. Просматривать, одобрять, редактировать и удалять отзывы и комментарии.
4. Просматривать и отмечать обработанными обращения через контактную форму.
5. Управлять учётными записями через встроенный раздел пользователей Django Admin при наличии соответствующих прав.

### Зарегистрированный посетитель

1. Смотреть опубликованные работы, искать их по названию и фильтровать страницу галереи по категории, стилю, технике, году и цене; получать сведения о работе на отдельной странице.
2. Отправлять сообщение художнику через общую контактную форму или форму конкретной работы.
3. Оставлять отзыв с оценкой от 1 до 5: не более одного отзыва на одну работу.
4. Оставлять комментарии к опубликованным работам.
5. Входить в свою учётную запись и выходить из неё.

### Гость

Гость может просматривать опубликованные работы, отправить контактное сообщение, зарегистрироваться и войти. Для отзыва и комментария требуется вход.

## 3. Бизнес-правила и валидация

1. У одного художника не может быть двух работ с одинаковым названием. Ограничение уникальности задано для пары `artist` + `title` в модели `Artwork`.
2. Выбранная техника должна относиться к выбранному стилю. Это проверяет метод `Artwork.clean()` при валидации модели, в том числе через форму Django Admin. Обычный вызов `save()` в коде сам по себе не вызывает `full_clean()`.
3. Оценка в отзыве должна быть целым числом от 1 до 5. Проверка задана валидаторами поля `Review.rating` и применяется при отправке формы.
4. Один пользователь может оставить только один отзыв о конкретной работе. Это проверяется перед сохранением; дополнительно в базе задано ограничение уникальности пары `artwork` + `user`.
5. Контактный адрес проверяется как адрес электронной почты полем `ContactRequest.email` и формой обращения.
6. Отзыв или комментарий можно создать только для опубликованной работы и только после входа. Автор берётся из `request.user`, а работа — из URL; посетитель не выбирает их полями формы.
7. Новый отзыв и новый комментарий имеют `is_approved=False`. Публичная страница показывает только одобренные записи. Средняя оценка и количество комментариев также учитывают только одобренные записи.
8. Пароль нового пользователя проверяет встроенная форма `UserCreationForm`; в базе он хранится в виде хеша, а не исходного текста.

## 4. Страницы и API

| Адрес | Назначение |
| --- | --- |
| `/` | Галерея опубликованных работ: поиск по названию, фильтры по категории, стилю, технике, году и цене. |
| `/artworks/<id>/` | Описание работы, цена, размеры, средняя оценка, одобренные отзывы и комментарии. |
| `/contact/` и `/artworks/<id>/contact/` | Обращение к художнику. |
| `/register/`, `/login/`, `/logout/` | Регистрация, вход и выход. |
| `/artworks/<id>/review/`, `/artworks/<id>/comment/` | Формы отзыва и комментария для вошедшего пользователя. |
| `/admin/` | Управление данными и модерация. |
| `/api/artworks/` | JSON-список опубликованных работ; доступен только метод GET. |

API использует Django REST Framework. Сериализатор `ArtworkSerializer` превращает объекты работ в JSON, включая вычисляемые размеры и ссылку на изображение. Фильтр `ArtworkFilter` принимает `style`, `technique`, `year_min`, `year_max`, `price_min`, `price_max`. Один и тот же фильтр используется в API и на HTML-странице галереи. Поиск по названию и категории дополнительно реализован на HTML-странице.

## 5. Данные и технологии

- Python и Django обрабатывают HTTP-запросы и формируют HTML-страницы.
- SQLite хранит пользователей, работы, справочники, отзывы, комментарии и обращения.
- Django ORM выполняет запросы к базе. `select_related()` используется для получения связанных автора, категории, стиля и техники работы без отдельных запросов на каждый объект.
- `Avg()` вычисляет среднюю оценку одобренных отзывов, `Count()` — число одобренных комментариев.
- Django Admin предоставляет интерфейс управления без разработки отдельной административной страницы.
- Django REST Framework и django-filter предоставляют JSON API и фильтрацию.

## 6. Проверка результата

1. Гость видит только опубликованные работы; черновик по прямой ссылке возвращает HTTP 404.
2. Регистрация создаёт обычного пользователя, но не даёт ему доступа к админке.
3. Некорректная форма не создаёт запись; корректная форма обращения, отзыва или комментария создаёт её.
4. Новый отзыв и комментарий не видны до одобрения администратором.
5. Повторный отзыв того же пользователя на ту же работу не создаётся.
6. API возвращает только опубликованные работы и применяет фильтры; POST-запрос к списку работ отклоняется.
7. Автоматические проверки запускаются командой `py manage.py test gallery` на отдельной тестовой базе.
